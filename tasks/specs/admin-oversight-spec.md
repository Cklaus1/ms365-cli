## Summary

Two read-only, admin-facing features:
1. **`ms365 reports …`**: Microsoft's aggregate usage reports. Tenant-level daily counts (email, Teams, active users) and a department roll-up. Counts only: **no message content, no per-person rows, and no department group smaller than 5 people.**
2. **`ms365 audit-trail`**: oversight of access itself. Who accessed which mailbox and how (owner, delegate, admin, app), which apps hold broad mail access, and which admin roles or consents changed. It reads Microsoft's audit log and directory, so it shows *access events and grants*, never the content that was accessed. (`audit-trail mailbox` creates a saved query with a POST; see AO-14/AO-25.)

Worked example that motivated AO-28..AO-32 (2026-10-17, done by hand from a Purview CSV export): a user read three delegated mailboxes (one of them a disabled admin account's) through a third-party connector that had tenant-wide delegated consent including `Mail.Read.Shared`. The commands in this spec answer exactly those questions without a manual export.

## Design rules

- **No collection of content.** ms365 gets no command that reads other people's mail, chats or calendars. Reports are Microsoft-computed counts; audit-trail prints an allow-list of access metadata (AO-9).
- **Small groups are never shown.** Department roll-ups pool groups under the minimum into one "Other" row and drop even that pool if it is under the minimum, so no row describes fewer than 5 people. The floor is not configurable below 5. Groups hidden at the floor stay hidden at every higher `--min-group-size` (AO-22).
- **Least privilege.** Per-workload audit scopes where Graph offers them (`AuditLogsQuery-Exchange.Read.All`, not `AuditLogsQuery.Read.All`).
- **Admins only, enforced by Microsoft.** Graph refuses callers without the reports/audit roles; the CLI maps those refusals to clear hints and adds no bypass.

## Acceptance criteria

1. No `reports` output contains a UPN or any per-person value (test over `by-department` with fixtures including small groups).
2. No roll-up row describes fewer than the minimum group size; a pool under the minimum is omitted; **no difference between two runs with different `--min-group-size` values describes fewer than 5 people** (AO-22, property test).
3. `--min-group-size` below 5 exits 2 with no request.
4. Concealed names produce a clear error naming the admin setting (exit 1), not an empty report.
5. A 403 from Graph maps to exit 4; the hint names Reports Reader (detail) vs Global Reader (tenant-level only) plus admin consent (AO-27).
6. `reports` commands succeed whether Graph answers JSON or a 302 → CSV, and the detail report is fully paged (two-page JSON fixture; CSV fixture with a quoted "Assigned Products") (AO-4, AO-23).
7. `audit-trail mailbox`, `access` and `import` output never includes a message subject, body, recipient, `InternetMessageId` or raw `auditData` (fixtures whose `auditData` contains `Item.Subject`, `AffectedItems[].Subject`, `Folders[].FolderItems[].InternetMessageId`).
8. Every `audit-trail mailbox|access` run prints the coverage line on stderr and never presents an empty result as "no access" (AO-12).
9. An audit query with `isRecordCountLimitExceeded: true` reports truncation and exits 0; a timeout exits 1 with a "narrow the window" hint; `failed`/`cancelled` exit 1 naming the status; a 403 exits 4 and distinguishes the Purview role from the Graph consent (AO-16).
10. `audit-trail mailbox a@x.com` keeps only records whose `auditData.MailboxOwnerUPN` is `a@x.com` (case-insensitive) (AO-9).
11. `audit-trail` is hidden from MCP tools, honors `--dry-run` (POST traced, no polling), and is blocked by `--read-only` (exit 4); `audit-trail import` works offline.
12. `audit-trail apps` lists an app whose only broad access is an `AllPrincipals` delegated grant with `Mail.Read.Shared`, marks external vs this-tenant and verified publisher (AO-28).
13. `audit-trail access` without `--app` or `--by` exits 2 with no request (AO-29).
14. `audit-trail import` on a 50,000-row file warns about truncation; on the worked-example fixture shape it reproduces the per-(actor, mailbox) aggregates (AO-31).
15. `ms365 chief …` no longer exists; README, snapshot, catalog, MCP and describe are consistent (AO-32).
16. Full suite, typecheck, `docs:check`, smoke and the dry-run snapshot stay green.
