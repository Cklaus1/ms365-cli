## Summary

Chief will use ms365-cli as its Microsoft 365 transport. This reverses ADR 0013, which rejected ms365-cli because its scopes are broader than Chief's own app (`<chief>/docs/adr/0013-gate-0-decisions.md:83-85`). The reversal holds only if ms365 ships two things: profiles whose scopes are a **ceiling**, and **broker-supplied tokens**. Chief keeps its own delegated Entra app with exactly `User.Read, Mail.Read, Calendars.Read, offline_access` for Gate 2, and it keeps no app-only access. Chief owns credentials and policy (ADR 0013 D5, `:101-103`). ms365 owns the Graph calls.

Today ms365 is built for one person at a terminal:
- Profile scopes only shape the login request. They are not a limit.
- A pre-obtained token works, but only by accident, and it still needs a client ID.
- Outputs carry no account, tenant or version, and a truncated `--all` only says so on stderr. `[REVISED: "no version" has no AH item → kept as a known gap, not built: `--version` is the hard-coded `0.1.0` (`src/index.ts:66`); Chief pins ms365 by the sha256 of the built `dist/` (MSC E7), which ADR 0014 condition 5 accepts]`
- `watch` keeps its own cursor and re-baselines silently when the delta token expires.
- Writes cannot be planned, approved and then applied exactly.
- `mail send` prints "Email sent successfully." for what Graph only accepted.
- Calendar writes do not know about series, occurrences or attendee notices.

This spec lists what ms365 must provide so that an agent host (Chief first, generic MCP agents second) can use it under the host's own Entra app and policy broker. Rule: judgment and state live in the host. Microsoft 365 operations live in ms365. ms365 gets no `chief` commands.

Everything else waits for Gate 3 (AH-5, AH-6, AH-7, AH-11), the Operator seat (AH-10), or later (AH-9). The tasks in this subset are marked **[G2]** in the task breakdown.

## Design rules

1. **Transport, not policy.** ms365 enforces the limits the host sets (ceiling, plan digest, version). It never decides whether an action is allowed. That is the host's job.
2. **No credential on argv, and no cache writes in external-token mode.** Other local users can read argv through `ps`. ms365 never writes a token it did not obtain itself.
3. **Unknown is not zero.** A partial list, a gap in a change feed, or an unknown send outcome must be stated **in band** (stdout JSON / NDJSON or the JSON error). Never only on stderr.
4. **The ceiling fails closed.** No env var, opaque token or dry-run skips it.
5. **One convention.** Build on the identity-profiles code on main (profiles, token sources, CredentialStore) and on the existing ledger (R-6/R-7, D23). Do not add a second profile or credential system. `[REVISED: was "Build on build/identity-profiles" → main, reason: merged]`
6. **Plain JSON contracts.** ms365 does not import Chief's schemas. Its fields map one-to-one onto them, and the mapping tables below are part of the contract.
7. Graph behaviour marked **†** is documented by Microsoft but not verified live. Each † is listed under "Needs a live tenant".
