# DRAFT — Dry-run fidelity: truthful, crash-free, offline, no secrets

**Status:** DRAFT — Step 1 adversarial review done 2026-10-14 against `41c41f3` (HEAD `b8b58d9`, same `src/`). Markers: `[REVISED …]`, `[ADDED …]`. No item removed. Not scheduled.

## Summary

`--dry-run` is the main way an agent previews a write. Right now it is wrong in four ways. It prints success lines for actions that never happened ("Email sent successfully."). It crashes or exits 1 in multi-step commands because the placeholder response `{dryRun,method,url}` gets read as real data. It needs a client ID, so it does not work fully offline. It prints request bodies, including the `drive share --password-stdin` password, to stdout, mixed in with the command's JSON. This spec makes dry-run output honest and parseable, and makes it exit 0 for every valid invocation. Evidence comes from `test/__snapshots__/snapshot.test.ts.snap`, plus a sweep of all 191 leaf commands run under `--dry-run` with every optional value flag set, against commit 41c41f3.

## Open questions

- **OQ1 — Which stream gets the dry-run trace? (needs-human)**
  - (a) Keep it on stdout.
  - (b) Send the `[dry-run]` lines to stderr. They are not affected by `--quiet`, because they are the point of a dry run. Stdout keeps the command's `-o` output, which is the placeholder `{dryRun,method,url,body}` with `body` redacted and parsed.
  - (c) Make stdout a single `{"dryRun":true,"requests":[…]}` document and suppress the command's own output.
  - **Recommendation: (b).** Stdout stays valid in every `-o` format, so jq, MCP `structuredContent` and `--fields` keep working. The preview stays machine-readable through the placeholder. (c) is more complete, but it changes the stdout shape for every command at once. `[REVIEW: X-9 recommends routing the trace through `info()` so `--quiet` drops it. This spec keeps the trace under `--quiet` (it is request evidence, not a confirmation) and lets `--quiet` drop only the DR-1 trailer. One owner must pick; see conflicts.]`
- **OQ2 — How to word success lines under dry-run? (engineering)**
  - (a) A wording per command, e.g. "(dry-run) Email not sent."
  - (b) `success()` stays silent under dry-run, and a `postAction` hook prints one trailer: `[dry-run] N request(s) previewed; nothing was sent.` `[REVISED: the trailer lives in `handleErrors`, not a Commander hook — see DR-1]`
  - **Recommendation: (b).** It is one convention, and future commands can't forget it.
- **OQ3 — Redaction scope (engineering).** Should message and post bodies (`content`) be redacted too? **Recommendation: no.** Showing the body is the purpose of a preview, and the user wrote it. Redact the credential-like keys only (DR-3) and truncate `contentBytes` (DR-4). Add no `--show-secrets` escape hatch.
- **OQ4 — Should dry-run skip delete confirmations? (needs-human)** The `confirm()` doc says it "always prompts so agents can't bypass". **Recommendation: skip under dry-run.** Nothing is sent, so nothing is bypassed. The `would ask:` line keeps the prompt visible. `[REVIEW: the premise "nothing is sent" holds only for Graph deletes; DR-22 closes the local-file case. Accepting OQ4 without DR-22 is a regression.]`
- **OQ5 — How should `cal update` get the zone? (engineering)**
  - (a) Print the GET and use the `<from GET>` marker.
  - (b) Hide reads that are only there to build the write.
  - (c) "Online dry-run": really send the GETs.
  - **Recommendation: (a).** (b) misrepresents what the real run sends. (c) breaks offline and needs auth (DR-16).
- **OQ6 — What should read-aggregate workflows print under dry-run? (engineering)**
  - (a) The trace only. `-o json` gives `{"dryRun":true}`.
  - (b) The report rendered with placeholders.
  - **Recommendation: (a).** A report built from no data is the untruthful output this spec removes.

## Acceptance criteria

1. Every leaf command in the dry-run snapshot, plus a second pass with every optional value flag set, exits 0 or 2 under `--dry-run`. Exit 1 or 3 fails the test, and so does exit 7 once OQ4 is accepted. The harness runs without `tty`.
2. Under `--dry-run`, stderr contains none of the DR-1/DR-2 confirmation strings. It ends with exactly one trailer line `[dry-run] N request(s) previewed; nothing was sent.`, where N equals the number of trace request lines. With `--quiet`, the trailer is absent and the trace lines remain (OQ1). This holds through `test/helpers/cli.ts` (`runCommand`), not only through `dist/index.js`.
3. `echo s3cret | ms365 --dry-run drive share D I --password-stdin` contains no `s3cret` on stdout or stderr, and does contain `"password":"<redacted>"`. A unit test covers `redactForPreview` on nested keys, `Authorization`/`Cookie` headers and `contentBytes`.
4. Assuming OQ1 (b): `ms365 --dry-run cal create … -o json` stdout passes `JSON.parse`, has `dryRun:true`, and has a `body`. Every `[dry-run]` line is on stderr. An MCP tool call with `--dry-run` returns `structuredContent`; a failing dry-run call still returns the JSON error line (`errorText`).
5. With `MS365_CLI_CLIENT_ID` unset and an empty `MS365_CLI_CONFIG_DIR`, `ms365 --dry-run mail send …` exits 0 and makes no network call and no file write under that directory. `[VERIFIED achievable: audit skips status 0 (graph-client.ts:134), the logger writes only with `MS365_CLI_LOG_FILE`, the idempotency ledger is skipped under dry-run (mail.ts:197, calendar.ts:181), and DR-16 never builds the token cache]`
6. `--dry-run workflow digest`, `standup` and `focus-time` print no report, exit 0, and in json mode print exactly `{"dryRun":true}`; their trace still lists every GET. `meeting-prep --event-id X` and `email-to-task M` (without `--list`) exit 0 and show the trace. `--dry-run mail triage` prints no "No messages found.".
7. `--dry-run mail list --all -o json` prints `{"value":[]}`; `-o table --all` prints an empty table, not a placeholder row.
8. `--dry-run watch mail --reset` leaves an existing cursor file byte-for-byte unchanged.
9. `user set-presence` reads the client ID from the profile when `--profile` sets one. Under dry-run with no ID, the body shows `"sessionId":"<client-id>"`. Live with no ID anywhere, it exits 3 with code `no_client_id` (shared with V-2).
10. `[REVISED]` `grep -rn '\.dryRun\b' src --include=*.ts`, excluding `graph-client.ts`, `index.ts` and `commands/mcp.ts` (CLI-option reads), returns nothing, and a test enforces it. `grep -rn "dryRun?: boolean" src/commands` returns nothing.
11. `[ADDED: DR-22]` `--dry-run auth profile delete p` with an existing profile exits 0, prints a `would delete` line, and the profile file is unchanged; same for `--dry-run auth logout` and the token cache / selected-account file.
