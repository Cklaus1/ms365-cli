# DRAFT — Performance and Developer Experience (P3 opportunities)

**Status:** DRAFT — must pass its own Step 1 adversarial review before any build. Not scheduled.

**As of:** 2026-10-14 · **Scope:** `src/**` at `41c41f3` (branch `build/ms365-findings-spec`) · **Source:** `tasks/opportunities.md` (P-7, warm MCP, `drive copy --wait`, MCP delta notifications, completion gaps) · **Format/severity:** as in `docs/ms365-findings-spec.md`. There are no legacy consumers (D27–D30), so nothing here needs a compat shim.

## Summary

Startup now takes about 85 ms (it was 70 ms at T05). **More than half of that, about 45 ms, is spent importing `@azure/msal-node`.** Registering all 26 command modules costs only about 6 ms. So the plan is a lazy MSAL import (X-1), not lazy command modules with stub registration (X-2, closed as not worth it). `mcp serve` pays the same 85 ms on every `tools/call` because each call spawns the CLI. Lazy MSAL cuts that to about 39 ms without any server redesign. The warm in-process server (X-4) is specified, but it is gated on a re-measure after X-1, because it needs every piece of process-global state made per-call. The rest is feature and DX work: `drive copy --wait` (X-7), MCP resource notifications driven by `watch` (X-8), four completion and table-column gaps, and three related issues found while verifying: dry-run needs a client ID (X-3), dry-run output on stdout isn't JSON (X-9), and `watch --follow` hangs over MCP (X-6).

## Open questions

- **OQ-1 (engineering): build the warm server at all?** (a) X-1 only, then re-measure; (b) build X-4 now. **Recommend (a).** After X-1 a spawned call costs about 39 ms. X-4 is worth doing only if the real-token path (cache file read plus `acquireTokenSilent`, not measurable here) adds more than about 50 ms per call on a logged-in machine. Record that measurement as the gate.
- **OQ-2 (engineering): concurrency for embedded calls.** (a) a mutex, so calls run one at a time; (b) an AsyncLocalStorage `CallContext` that holds the X-5 state and output sinks. **Recommend (a) first.** Graph latency dominates and agents rarely fan out. (b) touches every setter but no command code, so it can follow later.
- **OQ-3 (engineering): embedded default.** (a) opt-in `--embedded`; (b) the default, with `--spawn` as the fallback. **Recommend (a)** for one release cycle. There are no legacy consumers, so flipping the default later costs nothing.
- **OQ-4 (needs-human): `drive copy` argument shape.** (a) ID-based (`<driveId> <itemId> --to-parent`), like `drive files`/`delete`; (b) path-based (`drive copy /a.docx /Archive/`), like `cp`/`ls`; (c) both. **Recommend (a)** now and (b) as a follow-up, because path resolution needs a GET for each side.
- **OQ-5 (needs-human, needs a Windows box): the PowerShell `.ps1` shim.** If X-12 testing shows native completers don't fire for `ms365.ps1`, choose between (a) documenting removal of the shim, (b) a custom `.ps1` entry point with `param([Parameter(ValueFromRemainingArguments)]$a)` plus a non-native completer, or (c) leaving it as is. **Recommend (a).**
- **OQ-6 (engineering): an `id` column in tables.** Values are cut to 50 characters (`formatter.ts:255`), and most Graph IDs are longer, so an `id` column would be truncated and unusable. **Recommend not adding one.** Point to `--fields id,…` or `-o json` in the table footer instead. For X-13, recommend the `$expand` option.
- **OQ-7 (engineering): MCP subscription cursors across restarts.** (a) `--reset` on the first subscribe of each server session; (b) resume the saved `mcp-<r>` cursor. **Recommend (a).** Resuming could replay days of changes into one `resources/read`.

## Acceptance criteria

1. On the same machine, `--version`, `--help`, `describe --json` and `--dry-run mail list` each take at most 50 ms (median of 25 runs). A test asserts that `@azure/msal-node` is absent from `process.moduleLoadList`/the loader cache after `ms365 --help` (X-1).
2. `env -u MS365_CLI_CLIENT_ID ms365 --dry-run mail list` exits 0 from a directory with no `.env` and prints the GET (X-3).
3. `ms365 --dry-run todo lists 2>/dev/null | jq .dryRun` prints `true`, and the dry-run MCP `tools/call` result has `structuredContent` (X-9).
4. The `watch` MCP tool has no `follow` or `interval` property, and a call without `name` writes the cursor `mcp-<resource>` (X-6).
5. `drive copy` with `--wait` against a mocked 202 + `Location`: the monitor is polled without `Authorization`; `inProgress`, then `completed`, prints the new item; `failed` exits 1 with `code:"copy_failed"`; `--timeout 1` exits 1 with `code:"timeout"` and the monitor URL. `describe` and `docs:check` pass (X-7).
6. MCP: `initialize` advertises `resources.subscribe`. After `resources/subscribe ms365://delta/mail` with a mocked runner that yields 2 NDJSON lines, the server emits one `notifications/resources/updated`, `resources/read` returns 2 changes, and a second read returns 0 (X-8).
7. Completion: a bash simulation of `--output = t` yields `table text`; zsh, fish and pwsh tests for `--output=t` yield `--output=table --output=text`; `mail list --v` offers no `--version`; the PowerShell script registers all three command names (X-10–X-12).
8. If X-4 is built: two back-to-back embedded calls (`--fields id` then no `--fields`; a failing call then a succeeding one) produce the same output and exit codes as the spawn runner, for every row of the X-5 table. The full suite stays green under both runners.
