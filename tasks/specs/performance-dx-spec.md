## Summary

Startup now takes about 85 ms (it was 70 ms at T05). **More than half of that, about 45 ms, is spent importing `@azure/msal-node`.** Registering all 26 command modules costs only about 6 ms. So the plan is a lazy MSAL import (X-1), not lazy command modules with stub registration (X-2, closed as not worth it). `mcp serve` pays the same 85 ms on every `tools/call` because each call spawns the CLI. Lazy MSAL cuts that to about 39 ms without any server redesign. The warm in-process server (X-4) is specified, but it is gated on a re-measure after X-1, because it needs every piece of process-global state made per-call. The rest is feature and DX work: `drive copy --wait` (X-7), MCP resource notifications driven by `watch` (X-8), four completion and table-column gaps, and issues found while verifying: dry-run needs a client ID (X-3, owned by DR-16), dry-run output on stdout isn't JSON (X-9, owned by DR-6), `watch --follow` hangs over MCP (X-6), and `--password-stdin` over MCP reads an empty password (X-15).

## Open questions

- **OQ-1 (engineering): build the warm server at all?** (a) X-1 only, then re-measure; (b) build X-4 now. **Recommend (a).** After X-1 a spawned call costs about 39 ms. X-4 is worth doing only if the real-token path (cache file read plus `acquireTokenSilent`, not measurable here) adds more than about 50 ms per call on a logged-in machine. Record that measurement as the gate.
- **OQ-2 (engineering): concurrency for embedded calls.** (a) a mutex, so calls run one at a time; (b) an AsyncLocalStorage `CallContext` that holds the X-5 state and output sinks. **Recommend (a) first.** Graph latency dominates and agents rarely fan out. (b) touches every setter but no command code, so it can follow later.
- **OQ-3 (engineering): embedded default.** (a) opt-in `--embedded`; (b) the default, with `--spawn` as the fallback. **Recommend (a)** for one release cycle. There are no legacy consumers, so flipping the default later costs nothing.
- **OQ-4 (needs-human): `drive copy` argument shape.** (a) ID-based (`<driveId> <itemId> --to-parent`), like `drive files`/`delete`; (b) path-based (`drive copy /a.docx /Archive/`), like `cp`/`ls`; (c) both. **Recommend (a)** now and (b) as a follow-up, because path resolution needs a GET for each side.
- **OQ-5 (needs-human, needs a Windows box): the PowerShell `.ps1` shim.** If X-12 testing shows native completers don't fire for `ms365.ps1`, choose between (a) documenting removal of the shim, (b) a custom `.ps1` entry point with `param([Parameter(ValueFromRemainingArguments)]$a)` plus a non-native completer, or (c) leaving it as is. **Recommend (a).**
- **OQ-6 (engineering): an `id` column in tables.** Values are cut to 50 characters (`formatter.ts:255`), and most Graph IDs are longer, so an `id` column would be truncated and unusable. **Recommend not adding one.** Point to `--fields id,…` or `-o json` in the table footer instead. For X-13, recommend the `$expand` option.
- **OQ-7 (engineering): MCP subscription cursors across restarts.** (a) `--reset` on the first subscribe of each server session; (b) resume the saved `mcp-<r>` cursor. **Recommend (a).** Resuming could replay days of changes into one `resources/read`. (DR-18 makes `--reset` a no-op under `--dry-run`, so a `mcp serve --dry-run` session simply never emits.)
- **OQ-8 `[ADDED]` (needs-human): `drive copy` next to `drive cp`.** `drive cp <localFile> <remotePath>` is an upload (`drive.ts:315`); `drive copy` would be a server-side copy. (a) Keep both names and cross-reference them in help; (b) rename `cp` to `put` (no legacy consumers, D27–D30) and keep `copy`; (c) name the new command `drive copy-item`. **Recommend (a)** for this build and log (b) as an opportunity; renaming touches V-18 (`drive cp` error path), the README and the skills output.
