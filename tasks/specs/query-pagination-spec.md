# DRAFT — Query quoting, pagination and name-resolution gaps

**Status:** DRAFT — must pass its own Step 1 adversarial review before any build. Not scheduled.

**As of:** 2026-10-14 · **Scope:** `src/**` at `41c41f3` (branch `build/ms365-findings-spec`) · **Source:** `tasks/opportunities.md` (T10, T14, T19, T30 entries) · **Format/decisions:** `docs/ms365-findings-spec.md` (D1–D30 apply; D24 and D27–D30 in particular: no tenant, so † items are built to documented Graph shape and mock-tested; one `{"value":[…]}` envelope; no compat shims).

## Summary

Three user-supplied search terms reach Graph `$search` without `kqlQuote`, so a `"` in the term breaks the query. About 30 collection commands call `client.request()` once and print `response.data`. `@odata.nextLink` is stripped from that output (`graph-client.ts:693`) and no `nextCursor` is added, so results are **silently truncated** at the first page, with no hint that more exist. Mail folder names resolve only in `mail list` and `batch-move`, and `resolveFolderName` itself misses nested folders and falls back to the raw input as an ID. The catalog's per-command scope lists can't express "the scope depends on `--entity`/`<resource>`". Because the pre-flight check accepts any one of the listed scopes, it passes commands that then fail with a 403 partway through. No unquoted OData `$filter` interpolation was found.

**Severity:** as in the findings spec (P0–P3). † = depends on documented Graph behaviour, not run against a live tenant.

**Step 1 review (2026-10-14, against `b8b58d9`):** every file:line re-checked. Markers: `[REVISED …]`, `[ADDED …]`. No item removed. Net: 1 line fix (Q-14), 5 revisions (Q-4, Q-8, Q-9, Q-15, Q-16), 1 new finding (Q-20), AC-2/3/4/6 tightened, tasks re-sequenced; see the two Step 1 sections at the end.

## Open questions

- **OQ-1 (engineering): How strictly to match mail-folder names.** (a) Reuse `resolve.ts`'s exact-then-prefix-then-substring match. (b) Allow only exact, case-insensitive matches for `mail-folder`. **Recommendation: (b).** Add a per-type `match: 'exact'` flag to `TypeSpec`. With (a), a unique prefix like `--folder Arch` silently picks a destination for `move`/`batch-move`. The `not_found` error already lists the available names.
- **OQ-2 (needs-human): Nested folders.** (a) Top level only. (b) Path syntax `Inbox/Projects`, walking `childFolders` one segment at a time. (c) Find a plain name anywhere with a capped breadth-first search. **Recommendation: (b), plus (c) as a fallback on a top-level miss**, capped at 500 folders, with `ambiguous_name` when two paths match. Path syntax is predictable for agents. The fallback covers the common "it's under Inbox" case. A folder name containing `/` must then be passed as an ID.
- **OQ-3 (engineering): Unpaged endpoints (`joinedTeams` †, `/me/drives`).** (a) Leave them as single requests. (b) Use `printList` anyway. **Recommendation: (b).** It gives one envelope and one set of flags everywhere (D27), and `--all` costs nothing when there is no `nextLink`.
- **OQ-4 (engineering): How pre-flight combines scopes.** (a) Keep any-of across the union. (b) Use CNF with per-option scopes, as in the design. **Recommendation: (b).** Any-of stays inside each clause, so false positives remain near zero, which was the reason for the original any-of rule (`preflight.ts:28`).
- **OQ-5 (needs-human): Least privilege at login.** Org-mode login requests `User.Read.All` (`auth.ts:62`). Should it request `User.ReadBasic.All` instead? The only command that uses the broader scope is `user list --select <non-basic fields>`. **Recommendation:** keep `User.Read.All` at login (`user list --select department` is a real use) and fix only the catalog (Q-18).
- **OQ-6 (engineering): Directory `$search` escaping (Q-3) is †.** **Recommendation:** implement `\"` escaping as documented, test it against mocks and mark it "unverified live" (D24).
